# Kiri Image Loader

A compact ComfyUI image loader, graph-aware metadata collector and PNG saver with automatic metadata inspection, focused prompt/seed/KSampler copy actions, dual IMAGE/MASK A/B passthrough/comparison sockets, a dedicated Loaded Image C output, a live in-node wipe preview, and source-specific file actions.

## Persistent live comparison previews and side order

- The latest generated A/B preview is stored in the Kiri node's serialized properties, then restored when ComfyUI reactivates or rebuilds that workflow tab. Switching to another workflow and back no longer requires another generation just to recover the comparison.
- The saved preview includes both comparison sides and the current divider position. Restore is accepted only while the saved A/B source identities still match the node's current connections; changing either source prevents an old comparison from being shown as current.
- In **Visible Preview Image → A on Right (Swap Sides)**, switch the comparison orientation so A appears on the right and B on the left. OFF keeps the default A-left/B-right arrangement. The setting persists with the workflow and changes only the displayed comparison; the A/B input sockets, output values, copy actions, and save-source selection remain unchanged. It also works with a restored comparison after switching workflow tabs.
- This stores only the downscaled display preview, not the original IMAGE/MASK tensors. It does not affect output values, image pixels, metadata export, workflow embedding, or image saving. A combined 8 MiB cap protects workflow size; unusually large preview payloads remain live for the current node session but are not embedded for tab reconstruction.

## Image Saving menu, Loaded Image fallback and output C

- **Save Path** and **File Name** now both default to completely blank. Saving is disabled unless both fields contain values; an empty field never silently defaults to `ComfyUI/output` or a default filename. A supplied path must be a valid relative subfolder under `ComfyUI/output` or a complete absolute folder path. Invalid save configuration is reported without interrupting passthrough outputs.
- Added a third output, **C (IMAGE)**, which always exposes the selected Loaded Image independently of A and B. This lets you connect A and B to other image sources while retaining a direct output for Kiri's selected file. If no selected file can be loaded, C returns a safe neutral IMAGE placeholder.
- Both unconnected A and B outputs now default to the selected Loaded Image (IMAGE). If a MASK is actually connected to either dual-type socket, that MASK is passed through unchanged. An empty-but-connected branch remains distinct from an unconnected branch and receives a typed neutral tensor rather than being replaced by the selected file.
- Live preview tracing follows an upstream Kiri A or B output back to the selected Loaded Image when that exact upstream input is unconnected. This makes first-node A/B fallback images visible immediately in a downstream Kiri A/B preview, while connected-but-not-yet-rendered branches remain unavailable and do not leak a stale selected image.
- The standalone **Image Saving** right-click submenu selects **Input A only**, **Input B only**, or **Both A and B**. It defaults to A to preserve the previous saving behavior. B saves use metadata collected from the graph contributing to B; they are exposed to downstream Kiri nodes as saved B outputs, not mislabeled as A.
- **Save Folder Organization** is an optional three-way choice in the same submenu and defaults to **None (Save Path)**. **Month (YYYY-MM)** stores every generation directly inside a month folder, such as `Save Path/2026-11/`; all images saved during November go into that same folder. **Month + Day (YYYY-MM/YYYY-MM-DD)** creates a day folder inside the month, such as `Save Path/2026-11/2026-11-24/`; all generations on November 24 go directly into that day folder. The correct month/day folder is created automatically when a save first occurs in a new month/day. No per-generation timestamp folders are created. Turning organization off returns to the original flat Save Path. Date boundaries use the ComfyUI host machine's local calendar date. When A and B are both saved by one execution, both outputs and their optional companion files use the same selected destination folder.
- When Both is selected, each branch is saved independently. If the filename template resolves to an existing name, Kiri never overwrites it: it adds a numbered suffix such as `_00001_`, `_00002_` and continues until a free name is found. Batch outputs and A/B collisions use the same collision-safe allocator.

## Visible preview selection and fallback

- The right-click menu now includes **Visible Preview Image** with four persistent choices: **Auto / Compare (A + B)**, **Image A only**, **Image B only**, and **Loaded Image only**. The preference is stored in Kiri's existing hidden serialized settings; it adds no visible widget or node-height change.
- **Auto / Compare** is the default and preserves the familiar behavior: when both connected A and B previews are available, Kiri shows the draggable wipe comparison; when only one branch has a preview, it shows that branch alone; when neither branch has a usable preview (for example, before an empty VAE Decode or subgraph output executes), the selected Loaded Image is shown as the final fallback.
- **Image A only** and **Image B only** are strict display choices. They show only their selected branch and remain blank if that specific branch has no preview; they never substitute the other branch or Loaded Image. **Loaded Image only** always shows the selected image regardless of connected A/B previews.
- These choices affect only the node's visible preview. They do not alter A/B tensor outputs, image saving, metadata provenance, copy/paste behavior, or downstream workflow connections.

## Subgraph-aware previews

- When A or B is connected to a ComfyUI subgraph output, Kiri traces the selected output slot to its exact interior node/output, including nested subgraphs. The subgraph may expose multiple image outputs without Kiri confusing their previews or source metadata.
- Kiri resolves external inputs on the subgraph boundary through the parent graph's input-link IDs. It deliberately avoids treating `SubgraphNode.getInputLink(slot)` as a normal input resolver.
- Preview and metadata discovery are optional UI integrations: failures or temporarily incomplete subgraph links are contained and cannot prevent ComfyUI's native node rendering. In Auto / Compare mode, if neither A nor B currently has a usable preview, the selected Loaded Image is used as the final visual fallback. Forced A-only and B-only modes remain blank when their selected branch is unavailable.
- Large preview-only comparison canvases are downscaled for display; actual IMAGE/MASK tensors and saved output pixels are not resized by this safeguard.

## Features

- Familiar Load Image-style frontend with the normal image selector/preview, dual-type A/B outputs, and dedicated Loaded Image C output.
- Two optional dual-type input sockets, displayed as **A** and **B**. Each accepts either `IMAGE` or `MASK` and has a matching dual-type output; a third **C (IMAGE)** output always exposes the selected Loaded Image. Usable tensor values are passed through unchanged; empty connected values are handled as typed neutral fallbacks rather than being indexed, saved, or allowed to crash the node. No image/mask conversion occurs for usable values.
- The existing socket IDs `image_in` and `mask_in` are retained so workflows made with earlier Kiri versions keep their connections. Their visible labels are now **A** and **B**.
- Output A and output B each default to the selected file IMAGE when their respective input is unconnected. Each incoming IMAGE or MASK socket independently overrides its paired output without conversion. Output C independently provides the selected file IMAGE even when A and B are both connected. To use the source file's alpha mask, connect the appropriate mask output explicitly.
- The A/B inputs and A/B/C outputs are connection points only; they add no controls, widgets, metadata panel, or node height.
- Reads metadata automatically and independently for **Image A**, **Image B**, and the node's **Loaded Image**. Connected image sources are traced back to their originating ComfyUI Load Image file or an unambiguous saved output image when possible. No queue/generation run is required for an already-loaded source.
- **Right-click anywhere on the Kiri node** to open its context menu, including when no image is selected, loaded, or previewed. The top-level **Embed Complete Workflow: ON/OFF** switch is always available there.
- The **Metadata Saving** right-click submenu has four independent, persistent switches: **Save Positive Prompt**, **Save Negative Prompt**, **Save Node Names (Nodes Used)**, and **Other-Platform Metadata**. These do not change the **Embed Complete Workflow** switch.
- Each source submenu keeps only four direct clipboard actions: **Copy Positive Prompt**, **Copy Negative Prompt**, **Copy Seed(s)**, and **Copy KSampler Settings**. All other fields remain available in the read-only **View All Metadata…** window; they do not each create another menu command.
- Positive and negative prompts are resolved independently by tracing text-bearing and conditioning connections behind the sampler's conditioning sockets, including `ConditioningSetArea`, `StringMultiline`, primitive string, and text-area nodes. CLIP/model-loader links are excluded from prompt text, so selector values such as `Auto (from checkpoint)` cannot contaminate a copied prompt. Both copy actions stay visible; a missing branch is shown disabled rather than disappearing.
- Each source submenu also has its own **Copy** action for the actual pixels of **Loaded Image**, **Image A**, or **Image B**. The **Loaded Image** submenu also has **Paste** to add a clipboard image as a new ComfyUI input file. Connected A/B copies use their exact output preview/saved output; Kiri does not substitute an ancestor image when a transformed source has no available output pixels. The menus also provide **Open Embedded Workflow** when that exact image contains a valid ComfyUI canvas workflow, plus **Open**, **Open File Location**, and **Delete Image (Recycle Bin)** when a real file can be resolved.
- PNG source submenus expose **Edit Metadata…**. The editor groups **Positive Prompt** and **Negative Prompt** under one **Prompts** category, followed by **Parameters** (sampler settings plus recorded image Width/Height). Kiri's internal JSON remains behind the scenes rather than appearing as a redundant raw editor category. Existing metadata in the selected source PNG is preserved unless edited under **Additional Metadata**; newly generated Kiri images receive native ComfyUI graph chunks only when **Embed Complete Workflow** is ON. Other PNG text chunks remain editable under **Additional Metadata**. Saving updates the original PNG's text metadata while preserving pixels, ICC profiles, EXIF and all non-text PNG chunks byte-for-byte. JPEG/WebP/TIFF/GIF/BMP metadata remains viewable but is not editable through this feature.
- After deleting an image to the Recycle Bin/Trash, the image selector refreshes and selects the first remaining file (or clears the preview if none remain).
- Live input preview: Kiri resolves each connected input link back to its upstream node and immediately uses an already-loaded frontend preview when available (including the built-in Load Image preview). It follows exact output slots through nested ComfyUI subgraphs using the subgraph output resolver; it does not use SubgraphNode.getInputLink() to resolve the boundary node's external inputs. Node preview lookups are graph-scoped to avoid collisions between equal local node IDs in different subgraphs. Kiri preview/metadata introspection failures are isolated from ComfyUI's native canvas draw call. When both are available, a draggable vertical wipe compares A (left) and B (right), with no A/B labels. Drag only the visible center handle to move the divider; clicking elsewhere in the preview does not nudge it. For upstream nodes that expose previews through ComfyUI's stored output/preview records, Kiri also reads those records. Nodes that expose no frontend preview still use the KJNodes Points Editor-style inline Base64 execution payload as a fallback; no temporary preview files are written and output tensors are never altered.
- When either live input is connected, Kiri takes ownership of the native preview source (`node.imgs` and, on newer frontends, the image-preview widget's `previewImages` argument). In the default Auto / Compare mode, connected A/B previews take priority over the selected file; if neither branch has a usable preview, the selected Loaded Image is the final fallback. The right-click Visible Preview Image selector can force A, B, or Loaded Image to display alone. Disconnecting inputs restores the normal selected-file preview in Auto mode.
- ComfyUI's standard upload button copies uploaded images into its configured `input` folder. Kiri uses that ComfyUI-managed copy for metadata reading, opening, revealing, and Recycle Bin actions; it does not make another copy.
- The image selector recursively discovers supported image files under ComfyUI's configured input directory, including nested subfolders. It uses `folder_paths.get_input_directory()` (including custom `--input-directory` values), not a hard-coded Documents or portable-install path.
- The node remains an output node so its preview refreshes when the workflow is queued even when none of A, B, or C is connected onward.
- Unknown and custom metadata remains inspectable in the categorized full metadata viewer, grouped by category rather than exposed as a large collection of copy commands. Editing is handled separately by the PNG-only **Edit Metadata…** tool.
- **Optional graph-aware image saving:** Kiri saves the selected A/B branch or both as PNGs only when BOTH visible fields are filled in. **Save Path** and **File Name** are blank by default, so an untouched node performs no file saving and only routes A/B/C. Choose **Image Saving** on the right-click menu: **Input A only** (default), **Input B only**, or **Both A and B**. Save Path accepts either a subfolder under ComfyUI's Output root or a complete absolute folder path; File Name supports patterns such as `Kirin Image [Gotten Seed]`. Tokens include `[Seed]`, `[Gotten Seed]`, `[Steps]`, `[CFG]`, `[CFG Scale]`, `[Sampler]`, `[Scheduler]`, `[Denoise]`, `[Date]`, `[Time]`, `[Counter]`, and `[Batch]`. There is no default path or filename. A same-name file is never overwritten; Kiri adds numbered collision suffixes (`_00001_`, `_00002_`, etc.), including when both branches save to the same name. Each branch's metadata is collected from only its own active upstream graph. Kiri walks the executed `PROMPT` graph upstream from the selected A/B input, collecting active node inputs and settings, separate positive/negative prompts (including upstream string and multiline nodes), sampler values, checkpoint/model, VAE, text encoder, LoRA, ControlNet, IPAdapter, CLIP Vision and upscaler references where recognizable. Generic serializable inputs from other contributing nodes are retained in a per-node record. Model files resolved through ComfyUI's registered folders receive SHA-256 hashes, cached by path/size/modification time. Kiri LoRA Loader rows are expanded from `loras_json` with separate model/CLIP strengths and nearby Civitai provenance sidecars; trigger-word fields are retained. Kiri CheckPoint Loader selections, including Auto/checkpoint-managed encoder and VAE choices, are captured as Kiri loader details.
- **Workflow embedding and metadata preferences are separate.** With **Embed Complete Workflow: ON**, the PNG contains the complete structured Kiri/ComfyUI graph records and visual workflow, subject to the independent positive- and negative-prompt privacy preferences. With it **OFF**, no ComfyUI `prompt`, `workflow`, Kiri graph, node-ID/input/link record, or full-workflow payload is written. The independent right-click preferences can still include readable prompt text, a plain node-name list, and parameter-only metadata for other apps/sites. Platform JSON is allowed when its target app expects a JSON parameter envelope, but Kiri never places ComfyUI node objects, node IDs, class types, input dictionaries, links or workflow arrays inside those platform records.
- A single additional **CUSTOM META** wildcard input accepts connected values of different ComfyUI types. When connected, its runtime value overrides the manual Custom Metadata text. Without a connection, use **Metadata Saving → Edit Custom Metadata** from Kiri's right-click menu. Scalars, strings, lists and dictionaries are preserved as structured JSON; tensors and runtime objects are represented safely by their type/shape or public attributes.
- The **Embed Complete Workflow** toggle is at the top of the right-click menu (not hidden under a submenu) and is OFF by default. OFF prevents Kiri from writing ComfyUI `prompt`/`workflow` chunks, Kiri graph records, node IDs/inputs/links, or the original full canvas graph. ComfyUI may still interpret the ordinary A1111-style `parameters` text and construct its own simplified, prompt-testable graph; this is not the original saved workflow. The independent **Other-Platform Metadata** switch may still write app-specific parameter JSON, Draw Things metadata, NovelAI metadata and platform handoff records; these contain generation parameters/resource references only and never ComfyUI node objects or graph structure. The independent prompt and node-name switches control their respective text records. When ON, full structured Kiri metadata, the active execution prompt and visual workflow are embedded. **Apply Generation Data to Node…** and **Open Embedded Workflow** are therefore available only for ON-mode images. Credentials and secret-like fields are redacted from generic metadata and embedded workflow data. ComfyUI's `--disable-metadata` option is respected.
- Saving can target A, B or both. IMAGE/MASK batches are saved as one PNG per batch item; MASK tensors are represented as grayscale PNGs. The tensor outputs themselves are passed through unchanged.
- File actions are restricted to image files inside ComfyUI-managed input/output/temp directories, including nested subfolders, or an exact external PNG path previously registered by Kiri's saver for the current session. External paths use opaque, short-lived tokens rather than accepting arbitrary paths from browser requests. Relative Save Path traversal and managed-image symlink escapes are rejected. The node's own image selector remains restricted to the configured input directory.

## Install

1. Stop ComfyUI.
2. Back up or remove the previous `ComfyUI/custom_nodes/KiriImageLoader` folder.
3. Extract the `KiriImageLoader` folder from this ZIP into `ComfyUI/custom_nodes/`.
4. Start ComfyUI again.
5. Add **Kiri Image Loader** from `Kiri/Image`.
6. Connect any IMAGE or MASK output to input A and/or input B. Their paired outputs pass the exact connected values onward. Drag across the existing preview to move the A/B comparison divider.

On Windows, the built-in Recycle Bin fallback works without extra packages. On macOS/Linux, install the listed dependency in ComfyUI's Python environment with `python -m pip install -r requirements.txt`.

## Image clipboard and empty-input safety

- The source-specific right-click menus for **Loaded Image**, **Image A**, and **Image B** include **Copy**, which places the actual displayed/source pixels on the system clipboard as PNG data. For connected A/B outputs, Kiri prefers the exact output slot or saved Kiri output rather than an ancestor file whose pixels may differ.
- The **Loaded Image** submenu includes **Paste**. Kiri reads an image from the browser clipboard where permitted, normalizes it to PNG, uploads it into ComfyUI's input folder, refreshes the image selector, and selects the new file. When clipboard-read permission is unavailable, Kiri provides a paste target for Ctrl+V / Cmd+V.
- Clipboard actions do not overwrite the original source files or alter connected A/B wires. Pasted images become new files in ComfyUI's input directory.
- Empty/bypassed IMAGE/MASK branches are treated independently. Valid connected tensors pass through unchanged; empty connected branches receive finite, correctly typed neutral tensors, while unconnected branches may still use the selected image's normal file/alpha fallback. A placeholder is never saved as a generated image.
- Empty tensors retain their own usable spatial dimensions and infer IMAGE versus MASK from tensor layout when the graph's dual-type socket does not identify the concrete output type. When possible, the missing branch borrows the other branch's dimensions.
- Frontend preview routing ignores zero-sized sources and clears stale graph previews. A chained Kiri node's combined canvas preview is never substituted for a missing exact A/B output slot.
- Regression tests cover clipboard copy/paste and mixed empty VAE Decode, bypassed and chained Kiri A/B branches, both-empty combinations, mixed valid/empty branches, and file fallback only on genuinely unconnected sockets.

## Metadata coverage

The reader inspects embedded metadata exposed by Pillow in PNG, JPEG, WebP, TIFF, BMP, and GIF images. Coverage includes:

- **A1111-compatible tools:** A1111, common Forge/SD.Next-style `parameters` strings, prompts, negative prompts, and generation settings.
- **SwarmUI:** `sui_image_params`, `sui_extra_data`, and `sui_models`, including model/LoRA names, weights, hashes, original prompts, and generation dates.
- **InvokeAI:** current `invokeai_metadata`, `invokeai_workflow`, and `invokeai_graph` records, plus legacy `Dream` records when present.
- **Easy Diffusion:** JSON-style prompt, negative prompt, seed, inference steps, guidance scale, sampler, model identifier, and other scalar fields.
- **Fooocus / Fooocus-MRE:** prompt/settings fields, Fooocus styles, V2 expansion, performance, sharpness, ADM guidance, adaptive CFG, and unknown fields.
- **NovelAI:** legacy metadata and the `stealth_pngcomp` alpha-channel payload used by stealth PNG metadata. The parser reads the compressed JSON payload and its prompt/settings fields; it does not validate NovelAI signatures or perform forward-error correction.
- **Draw Things:** reads the nested RDF/XMP `dc:description` and `exif:UserComment` properties, including its compact JSON fields and LoRA records. Generic XMP properties and unknown values remain available in the full metadata viewer.
- **Naifu:** common prompt/negative-prompt and generation fields in JSON-style records.
- **ComfyUI:** when present, `prompt` and `workflow` JSON, common sampler/checkpoint/LoRA/text-encode node inputs, and workflow widget values. A valid embedded canvas `workflow` graph is also made available to **Open Embedded Workflow**. Kiri writes its own native ComfyUI graph chunks only when **Embed Complete Workflow** is ON.
- **Generic image metadata:** EXIF text and otherwise-unrecognized scalar or structured metadata exposed by Pillow.

The reader also normalizes nested PixAI API, Tensor.Art TAMS, Civitai resource, Easy Diffusion task and Kiri platform-handoff objects into copyable parameter fields. Civitai resource/version IDs are kept as Civitai IDs; PixAI and Tensor.Art model/LoRA IDs are kept in their own provider namespaces. Structured JSON and unknown fields remain available in **View All Metadata…**. JSON/handoff rows have a **Copy JSON** action for pasting the full request/parameter object into the target app or API tool.

Compatibility levels are deliberately separated: ComfyUI, A1111-compatible PNG metadata, SwarmUI, Fooocus, NovelAI and Draw Things have recognized native metadata records; Easy Diffusion receives a documented task JSON companion; InvokeAI receives portable generation metadata (not a fabricated workflow or catalogue model identity); Civitai resource provenance is retained; PixAI and Tensor.Art receive API-shaped handoff requests that still need their own native model/LoRA IDs; SeaArt, TensorHub / Cozy Creator and Naifu receive copyable parameter handoffs where a verified native image-import contract is unavailable.

Compatibility depends on metadata actually being embedded in the file. Re-encoding, social sites, or chat services may strip it. ComfyUI workflows can contain many inactive branches and custom nodes; this reader surfaces common node fields and raw workflow JSON but cannot infer every custom node's semantics. Metadata keys and semantics remain vendor-specific. Video containers are not supported.

## Universal metadata exports

Open **right-click → Metadata Saving → Compatibility Export Settings…** to configure the target formats. Three quick switches sit directly above that dialog in the same right-click submenu and persist with the node:

- **Save Positive Prompt** and **Save Negative Prompt:** independent controls for the respective prompt branch in Kiri's saved A-image metadata, B's execution-time metadata record, and parameter-only platform exports. Turning one OFF removes only that branch's text; the other branch remains available. A shared upstream text node remains only when at least one branch using it is enabled. If full workflow embedding is ON, graph structure and sampler/model connections remain, while only the disabled branch's text-bearing widgets are blanked.
- **Save Node Names (Nodes Used):** controls the additional readable `Kiri Nodes Used` plain-text list, using custom display titles where available and implementation names otherwise. It contains names only, not IDs or serialized node data. If full workflow embedding is ON, the complete workflow itself still necessarily contains its node names.
- **Other-Platform Metadata:** independently enables/disables non-ComfyUI app/site records, including the selected `parameters` profile, InvokeAI, Draw Things, NovelAI, the universal handoff bundle and configured companion files. With this OFF, Kiri uses plain A1111-style parameter text and does not emit those platform adapters.

The workflow switch controls a different thing: whether ComfyUI-loadable graph data is embedded. With **Embed Complete Workflow OFF**, Kiri never writes the ComfyUI `prompt` or `workflow` chunks, `kiri_metadata` graph records, or custom ComfyUI node JSON. Other-platform records may still be JSON when their destination format requires JSON, but they are generated from a strict parameter/resource projection with no ComfyUI node objects, IDs, class types, input dictionaries, links or workflow arrays. With **Embed Complete Workflow ON**, Kiri additionally writes the canonical Kiri graph record, active ComfyUI execution prompt and complete visual workflow.

The NovelAI payload is unsigned and has no optional forward-error-correction block; Kiri does not forge NovelAI signatures. InvokeAI catalog-bound model identifiers are included only when a complete native identifier was supplied, never fabricated from a filename or SHA-256.

The single PNG `parameters` key can contain only one of these incompatible profiles at a time. Choose it in **Compatibility Export Settings…**:

- **A1111 / Forge / Civitai-compatible:** conventional prompt/negative prompt/parameter text. When actual Civitai version IDs are present in Kiri LoRA Loader provenance, Kiri writes the Civitai `Civitai resources:` details block. Civitai IDs are never reused as PixAI/Tensor.Art IDs.
- **SwarmUI:** SwarmUI's JSON `sui_image_params` / `sui_extra_data` / `sui_models` envelope. Kiri includes model/LoRA names and strengths; it writes the `sui_models.hash` value only if a SwarmUI tensor hash was explicitly supplied. It never mislabels a whole-file SHA-256 as a tensor hash.
- **Fooocus / Fooocus-MRE:** Fooocus JSON scheme with the `fooocus_scheme` marker, prompt, negative prompt, resolution, common generation controls, base/refiner model hints, styles and LoRA settings. Use Fooocus's **Load Parameters** flow; unsupported/absent Fooocus-specific settings remain unset.
- **Easy Diffusion:** documented `numOutputsTotal` + `reqBody` task JSON. In addition, Kiri writes a matching `.easy-diffusion.json` task file by default; drag that companion JSON onto Easy Diffusion to load the fields it supports. The image itself is not claimed to contain Easy Diffusion's proprietary private image-restore payload.

The `kiri_interop` manifest carries normalized generation settings and platform handoff payloads. PixAI v2 and Tensor.Art TAMS request objects are structured for their documented APIs; submission still requires the corresponding provider-native model and LoRA IDs. The adapter only uses IDs already present in provider-specific provenance. It does not infer them from Civitai IDs, local filenames or hashes. Civitai receives its own resource-version details where those IDs are available. SeaArt and TensorHub / Cozy Creator are editable handoff templates because a stable public native image-to-parameter-import contract could not be verified; their website **Reuse Parameters** controls are not guaranteed to accept a Kiri PNG directly. Naifu images are readable, and Kiri also writes a copyable Naifu-style parameter handoff (prompt, negative prompt, dimensions, seed, steps, scale, sampler, scheduler, model hint and LoRAs). This is a convenience mapping for compatible local builds, not a claim that every Naifu fork can import a PNG or JSON through one native command.

The optional **Also write a .kiri.json sidecar** setting is OFF by default. When enabled together with **Other-Platform Metadata**, Kiri writes a companion file next to each image. With workflow embedding ON it can contain the complete Kiri record; with workflow embedding OFF it contains only the parameter/resource-only platform projection and never ComfyUI node graph data. The Easy Diffusion task JSON is a separate option and is ON by default when Other-Platform Metadata is enabled. Fooocus and Naifu handoffs are also emitted as named JSON chunks in the universal bundle so they can be copied from the metadata viewer. If the PNG is later edited through **Edit Metadata…**, Kiri also attempts to synchronize an existing `.kiri.json` sidecar.

## Automatic graph-aware metadata saving

Kiri is an output node, but image saving is optional. **Save Path** and **File Name** both start blank; if either is blank, no image is written and all A/B/C outputs continue normally. When both fields are configured and valid, Kiri saves the primary **A** output into the chosen folder as a PNG. This is separate from the live in-node preview: preview JPEGs are display-only, while the saved PNG contains the embedded metadata. The original IMAGE/MASK output tensors are returned unchanged. B is not saved as a second file because it is the independent comparison source; after execution, its own connected graph metadata is still available from the Image B submenu. For an IMAGE batch, each item is saved as its own PNG. If A carries a MASK tensor, its grayscale mask representation is saved.

### What Kiri collects

Kiri receives ComfyUI's hidden execution `PROMPT` and walks upstream from its **Image A** input. It records the nodes that actually appear in the executed prompt path, following their connected inputs recursively. Unrelated branches are not included. Kiri also checks the visual workflow's LiteGraph mode-4 bypass markers, skips those nodes, and rewires their outgoing links through the matching upstream input before recording the active graph. The image-producing branch is the metadata scope; the Image B comparison branch is not mixed into the saved A image's generation settings.

Recognized categories include positive/negative text conditioning, sampler and guider settings (seed, steps, CFG, sampler, scheduler, denoise and other recognized inputs), checkpoint/diffusion model names, VAE names, text encoder names, LoRA names and strengths, ControlNet, IPAdapter, CLIP Vision and upscaler resources. Where a registered model file can be resolved through ComfyUI's model folders, Kiri calculates its full SHA-256 hash and caches it for the current ComfyUI process using the resolved path, file size and modification time. First-time hashing of very large files can take additional time.

Kiri also retains the serializable inputs from every collected upstream node in `kiri_metadata.graph.active_upstream_nodes`. This generic per-node record is intended to preserve custom-node settings even when Kiri does not know their semantics. Known categories are additionally summarized into dedicated fields and a conventional A1111-style `parameters` text chunk for interoperability. Values held only in private runtime state, or opaque objects that expose no serializable public data, cannot be reconstructed; opaque objects are represented by their type rather than dumping arbitrary memory representations.

When **Embed Complete Workflow** is ON, the Kiri-owned `kiri_metadata.graph.active_upstream_nodes` record retains serializable inputs for nodes contributing to Image A, supporting detailed metadata inspection and **Apply Generation Data to Node…**. The active execution prompt and full visual workflow are also embedded. When OFF, Kiri writes no ComfyUI graph record: no `prompt`/`workflow` chunks, Kiri node IDs or inputs, or node-link topology. The independent **Other-Platform Metadata** option may still write platform parameter JSON, but those records contain generation parameters and resource references only—not ComfyUI nodes or graph structure. **Apply Generation Data to Node…** and **Open Embedded Workflow** are unavailable for OFF-mode images.

### Metadata controls

- **Save Positive Prompt** and **Save Negative Prompt:** right-click → **Metadata Saving**. Each applies independently to Kiri's saved A-image record, B's runtime graph metadata, and platform parameter records. The disabled branch is removed without removing KSampler settings, checkpoint/VAE/text-encoder references, LoRA names/weights/hashes, or other resource provenance. With workflow embedding ON, only prompt text widgets belonging exclusively to the disabled branch are blanked; graph topology and generation parameters remain.
  These are node-wide preferences used for metadata Kiri creates. A is the saved PNG output; B receives execution-time metadata but is not saved as a second PNG. **Loaded Image** is an existing source file: merely selecting it never rewrites that file. When it is passed through and saved as A, the same preferences apply to the new output; direct changes to the original Loaded Image still require **Edit Metadata…** and an explicit save.
- **Save Node Names (Nodes Used):** controls the separate plain-text `Kiri Nodes Used` list. The list contains display names only. Turning it OFF does not remove node names from a complete workflow when **Embed Complete Workflow** is ON, because those names are intrinsic to the workflow graph.
- **Other-Platform Metadata:** independently controls app/site parameter records and companion files. When OFF, Kiri suppresses those adapters and uses plain A1111-style `parameters` text. When ON, it may write JSON formats required by target applications, but these are parameter/resource records only and never contain ComfyUI node objects, node IDs, input dictionaries, links or workflow arrays.
- **Embed Complete Workflow:** top-level toggle in the node's right-click menu; defaults to OFF. OFF prevents Kiri from embedding its ComfyUI execution prompt, visual canvas workflow, or structured Kiri node graph. The ordinary A1111-style `parameters` text can still be interpreted by ComfyUI as a simplified, prompt-testable graph; this is generated by ComfyUI from portable sampler parameters, not the original saved canvas workflow. OFF does not disable the independent prompt, node-name, or other-platform metadata preferences. ON restores the full structured Kiri metadata, active execution prompt, and visual canvas workflow.
- **Custom Metadata:** choose **Metadata Saving → Edit Custom Metadata** to open a temporary multiline editor. The editor is not a permanent node widget and does not change the node's height. You can enter free-form text or JSON.
- **CUSTOM META input:** one optional wildcard socket accepts connected ComfyUI values. If connected, its runtime value takes priority over the manual editor. Strings, numbers, booleans, lists and dictionaries are serialized as their corresponding JSON values. Tensors are summarized by shape/dtype/device; ordinary custom objects are serialized from public attributes where available, otherwise represented by a safe type label.

Credential-like fields (API keys, tokens, passwords, secrets, authorization values and similar keys) are redacted from generic metadata and opt-in workflow data. ComfyUI's `--disable-metadata` launch option is respected: Kiri still writes the PNG image but omits embedded metadata.

Saving is disabled by default. Both **Save Path** and **File Name** must be filled in before Kiri writes a PNG. A relative Save Path is placed under `ComfyUI/output` (for example `Kiri Images/Characters`); a complete absolute path can target another folder. For example, `Kiri Images/Characters` plus `Kirin Image [Gotten Seed]` creates `ComfyUI/output/Kiri Images/Characters/Kirin Image 123456.png` for seed `123456`. Supported filename tokens are `[Seed]` / `[Gotten Seed]`, `[Steps]`, `[CFG]` / `[CFG Scale]`, `[Sampler]`, `[Scheduler]`, `[Denoise]`, `[Date]`, `[Time]`, `[Counter]`, and `[Batch]`. Existing files are not overwritten; Kiri adds a numbered suffix if the rendered name already exists. For absolute paths outside `ComfyUI/output`, Kiri gives the browser an opaque, session-limited file reference for metadata and file actions; it does not expose arbitrary filesystem paths through the HTTP endpoints. Kiri does not write the preview payload to disk, create temporary preview files, or change the actual IMAGE/MASK tensors passed downstream. If saving fails, the error is reported in Kiri's execution UI/log and the original passthrough outputs remain available.

## Right-click menu behavior

The extension intercepts the canvas context menu whenever the selected node is Kiri, not only when the pointer is over the image preview. This keeps the workflow-embedding switch reachable with an empty node. The Kiri menu contains separate source submenus: **Image A**, **Image B**, and **Loaded Image**. Connected inputs follow their own upstream graph links; pass-through/transform chains inherit file metadata only when there is exactly one unambiguous image-file ancestor. A generated A tensor with no original image file resolves to the PNG Kiri saves for that execution. Generated B tensors receive graph-only metadata from their own active upstream branch; B is not written as an additional output file. The selected filename is never substituted for an unrelated connected tensor.

## Open Embedded Workflow

Each source submenu (**Image A**, **Image B**, and **Loaded Image**) conditionally exposes **Open Embedded Workflow** when that source image contains a valid ComfyUI canvas workflow graph (`nodes` and `links`). Selecting it creates a new temporary workflow tab through ComfyUI's frontend workflow store and opens the recovered graph there. The current workflow tab and its unsaved edits are left intact. Opening a workflow does not queue or execute it.

The action is intentionally not shown for ordinary A1111 parameter strings, ComfyUI API-prompt-only JSON, InvokeAI workflow/graph records, or images without a valid ComfyUI canvas graph. Those records remain available in **View All Metadata…**. If a ComfyUI frontend does not expose its workflow-tab API, Kiri reports that limitation and leaves the current canvas unchanged rather than replacing it.

Embedded workflow data is untrusted user-provided metadata. Opening a workflow reconstructs its node graph, but does not include the checkpoint files, custom-node packages, or external input assets it references. Missing dependencies may need to be installed or paths repaired before the recovered workflow can run.

## Editing embedded PNG metadata

Choose **Edit Metadata…** from a PNG source submenu to open the internal editor. One **Prompts** section contains separate Positive Prompt and Negative Prompt fields, avoiding a repeated Negative Prompt category heading. **Parameters** lists recognized generation settings and recorded Width/Height. Width and Height are metadata values only; changing them does not resize or re-encode the picture. Full-workflow images update their structured Kiri/platform records. Workflow-OFF images remain free of ComfyUI graph records when edited; parameter-only platform JSON is preserved only when the image mode marker permits those exports. Other editable text chunks appear under **Additional Metadata** for full-metadata images. Save writes changes into the original PNG, not a sidecar or second image.

The update is performed as an atomic file replacement. The PNG's compressed pixel-data chunks (`IDAT`) and all non-text chunks (including color profiles and EXIF chunks) are streamed through byte-for-byte; only `tEXt`, `zTXt`, and `iTXt` chunks are replaced with UTF-8 `iTXt` chunks. This is lossless for the image pixels and does not re-encode the image. Keep a separate copy of an important image before editing its metadata. The current editor supports PNG only; other image formats remain read-only.

## File-action behavior

- **Open:** launches the exact source file using the operating system's default file association on the machine running ComfyUI.
- **Open File Location:** Windows Explorer selects the exact source file; macOS Finder reveals it; Linux opens the containing directory (file selection is not standardized across Linux file managers).
- **Delete Image (Recycle Bin):** immediately moves the exact source file to the operating system Recycle Bin/Trash without confirmation. When the source is a standard Load Image node in the input directory, its selector refreshes to the next available image. This is recoverable through the OS trash interface.

These actions run on the ComfyUI host, not necessarily the machine running the browser. They are intended for a local ComfyUI installation. Moving to the Recycle Bin/Trash is performed on the host running ComfyUI. The node never falls back to permanent deletion. On Windows, a native Recycle Bin fallback is included. On macOS/Linux, install the `send2trash` dependency if it is not already available.

## Important behavior

Metadata extraction is a frontend-triggered, read-only request to the local ComfyUI server. It runs independently of `load_image` execution. The Loaded Image metadata source always refers to Kiri's filename selector. Image A and Image B metadata sources follow their respective connected input links and trace upstream through pass-through/transform nodes only when one original file can be identified unambiguously. Each source has an independent cache/request token, so a late metadata response for one image cannot replace another image's menu. Generated A outputs are saved by Kiri and their PNG metadata is available from Image A after execution. Generated B outputs expose metadata from their own upstream execution graph without creating another saved image. File actions are shown only when an actual source file can be resolved.

The optional dual-type input/output pairs are independent overrides:

| Input A (`image_in`) | Input B (`mask_in`) | Output A | Output B | Output C | Default preview |
|---|---|---|---|---|---|
| disconnected | disconnected | Selected file IMAGE | Selected file MASK | Selected file IMAGE | Loaded Image |
| IMAGE or MASK | disconnected | A tensor, unchanged | Selected file MASK | Selected file IMAGE | A alone |
| disconnected | IMAGE or MASK | Selected file IMAGE | B tensor, unchanged | Selected file IMAGE | B alone |
| IMAGE or MASK | IMAGE or MASK | A tensor, unchanged | B tensor, unchanged | Selected file IMAGE | Draggable A/B comparison |

Outputs A and B are `IMAGE,MASK` multi-type sockets; output C is a dedicated `IMAGE` socket for the selected Loaded Image. They accept downstream image or mask consumers as appropriate. Valid input tensors retain their actual type, data, and identity; a connected-but-empty branch receives a finite neutral tensor of the inferred type so it cannot break mixed downstream graphs. Preview generation uses the first item of each usable batch for display only; the full original batch is passed through to the outputs.

When an upstream node already exposes its loaded image or preview in the ComfyUI frontend, Kiri can display it as soon as the connection is made and refresh it when that upstream preview changes; no Kiri execution or diffusion generation is needed for that case. If an upstream node exposes only a server-side tensor and no frontend preview record, its image cannot be read by browser code until that node executes and sends preview data. Kiri retains the Points Editor-style execution-payload fallback for those nodes. Intermediate per-step sampler previews remain a separate capability.

## Apply Generation Data to an Existing Node

Each source submenu (Image A, Image B, or Loaded Image) can expose **Apply Generation Data to Node…** when an executed graph with compatible node/widget data is present.

The importer is intentionally destination-driven and explicit:

1. Select an original source node from the image's recorded active graph.
2. Kiri lists nodes in the current graph with the exact same ComfyUI node implementation type.
3. Select the exact destination node, even when multiple identical samplers or loaders exist.
4. Review the same-named scalar widgets that can be transferred, uncheck anything to preserve, then apply.

Node IDs are shown for reference only. IDs from the source image are never used to select a destination. Node titles, source IDs, and workflow UUID are context; the user chooses the actual destination object in the current graph. This supports the same node type in a completely different canvas position/order and avoids guessing between multiple KSampler Advanced stages.

Only scalar widget values with matching input/widget names are candidates. Link arrays, structured objects, MODEL/CLIP/IMAGE/conditioning connections, and destination widgets whose corresponding sockets are connected are excluded. Existing graph connections and node layout are never rewritten. Combo values missing from the local option list are added to that widget's choices so the imported selection remains visible.

Kiri LoRA Loader's hidden canonical `loras_json` / trigger fields are transferable; after import, its own `onConfigure` handler rebuilds the dynamic LoRA rows. Kiri CheckPoint Loader selections and ordinary widgets (for example KSampler/KSampler Advanced settings and text-node values) use their native widget callbacks.

The importer reads an explicit `generation_data` payload from Kiri metadata. For other ComfyUI PNGs it can fall back to the executed API `prompt` chunk and decorates nodes with titles/workflow identity when an embedded canvas workflow is available. It does not import or replace an entire workflow. It currently targets nodes in the same active graph/subgraph as the Kiri Image Loader instance; nested or other open tabs must be opened as the current graph before importing.
